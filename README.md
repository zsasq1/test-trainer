# Тренажёр тестов

Веб-версия тренажёра для iPhone: вопросы из JSON — один ответ, несколько ответов, выпадающий список, порядок, текстовый ответ, кейсы; звёздочки, поиск, свои тесты с баллами.

**Открыть:** ссылка GitHub Pages этого репозитория (Settings → Pages).

На iPhone: открыть в Safari → «Поделиться» → «На экран „Домой“». Работает без интернета.
Свой JSON: ☰ → «Мои файлы» → «Загрузить JSON» (хранится только на телефоне, другим не виден).

## Факультеты и файлы курсов

При первом заходе студент выбирает факультет: Лечебное дело (6 курсов), Педиатрия (6 курсов) или Стоматология (5 курсов). Он видит тесты только своего факультета.
Всё, что было загружено раньше, — Лечебное дело. Кто уже пользовался сайтом, считается студентом Лечебного дела.

Где лежат файлы:
- Лечебное дело — как и раньше, `data/<курс>/…` (например `data/3/topka.json`).
- Педиатрия — `data/ped/<курс>/…`, Стоматология — `data/stom/<курс>/…` (например `data/ped/2/anatomiya.json`).
- Список всех файлов — `data/sets.json`: у каждого файла есть название, курс и факультет (`"fac": "lech"`, `"ped"` или `"stom"`; без `fac` — Лечебное дело).

Удобнее всего — через админку: `admin.html` (в тренажёре: поиск «админ» или ☰ → Настройки → Админка).
Вход — токен GitHub с доступом Contents: Read and write к этому репозиторию; он хранится только на устройстве владельца.
Как добавить тест: в «Файлах курсов» выберите факультет (Лечебное дело / Педиатрия / Стоматология), затем курс и нажмите «Добавить файл в … курс · …».
Админка сама коммитит файл в папку этого факультета и курса и обновляет `data/sets.json`. Удаление и переименование тоже работают внутри выбранного факультета.

Вручную: положите `*.json` в папку курса — Лечебное дело `data/1` … `data/6`, Педиатрия `data/ped/1` … `data/ped/6`, Стоматология `data/stom/1` … `data/stom/5` — и выполните:

```
git pull
python3 собрать.py
git add -A && git commit -m "Обновил вопросы" && git push
```

## Вид

Экран повторяет систему тестирования INDIGO: шрифт Verdana, бледно-голубые рамки и кнопки, вопрос в белой панели, вверху «Вопрос №N из M». После «Проверить» над ответом появляется строка «Верный ответ (балл 1 из 1)» зелёным, «Неверный ответ» красным или «Вопрос пропущен» серым, а при ошибке ниже — «Правильный ответ:» в том же виде. В тесте проверенный вопрос закрывается (ответ уже не поменять), слева «Закончить», рядом баллы.

Тёмная тема включается сама, когда на телефоне или компьютере включён тёмный режим: тёмно-синий фон, те же голубые рамки и кнопки. Выбрать вручную — ☰ → Настройки → Тема: «Как на устройстве» (по умолчанию), «Светлая» или «Тёмная». Выбор хранится на этом устройстве (`localStorage`, ключ `TestTrainer.theme`); цвета — переменные в начале `<style>` в `app.html`, тёмные — в блоке `prefers-color-scheme: dark` и `:root[data-theme="dark"]`.

Админка (`admin.html`) в том же виде и с теми же цветами (переменные скопированы из `app.html` — меняя палитру, поменяйте в обоих файлах). Вверху справа переключатель темы: ◐ как на устройстве · ☀ светлая · ☾ тёмная. Он общий с тренажёром: тема, выбранная в админке, действует и в тренажёре на этом устройстве, и наоборот.

## Языки

При первом заходе по очереди: язык (Русский / English / العربية), факультет, курс. Кто уже пользовался сайтом, остаётся на русском и на своём факультете.
Язык меняет только интерфейс: вопросы показываются так, как они написаны в файле. По-арабски интерфейс зеркальный (справа налево), а русский вопрос остаётся слева направо.
Сменить язык — ☰ → Настройки → Язык. Админка остаётся на русском.

Переводы — словарь `TR` в начале скрипта `app.html`: русская фраза → [английский, арабский]. Новая фраза без перевода показывается по-русски.

## Счётчик «сейчас в сети»

Firebase Realtime Database: адрес базы в `FIREBASE_DB` — в `app.html` и в `admin.html` (одинаковый).
Гость пишет только случайный номер и время; у вошедшего в аккаунт рядом стоит его uid.

## Аккаунты

После 5 ответов сайт просит зарегистрироваться: имя пользователя и пароль.
- Пароли хранит Firebase Authentication. Вход идёт по случайной служебной почте `…@users.example.com`: на неё ничего не отправляется.
- `logins/<имя>` — кому принадлежит имя. Имя сравнивается без учёта регистра и пробелов, «ё» = «е». Занять чужое имя не дают правила базы.
- `users/<uid>` — имя, факультет (`fac`), курс, когда заходил. Сменить имя можно один раз, это тоже проверяют правила. В админке рядом с курсом виден факультет.
- В админке аккаунты можно блокировать и удалять. Заблокированный видит «Доступ закрыт». Удаление освобождает имя.
- Вход через Google: кнопка «Продолжить с Google» (видна, если заполнен `GOOGLE_CLIENT_ID` в `app.html`). Google возвращает человека на сайт, Firebase проверяет вход, и человек один раз выбирает имя пользователя. В `logins` у такого аккаунта стоит `g:<uid>`.
- Вход через Telegram: кнопка «Продолжить с Telegram» (видна, если заполнены `TG_BOT`/`TG_BOT_ID` и `TG_WORKER` в `app.html`). Основной способ — в одно нажатие: кнопка открывает бота по ссылке `t.me/<бот>?start=<код>`, человек жмёт «Запустить», Telegram сообщает об этом Worker'у (вебхук), а сайт ждёт подтверждения кода и сам входит. Код одноразовый и живёт 10 минут. Запасной способ — по номеру телефона через страницу Telegram (ссылка «Нет Telegram на этом устройстве?»); его подпись тоже проверяет Worker. Всё это делает Cloudflare Worker из папки `telegram-worker/`: секретный токен бота хранится только там. После выкладки Worker'а один раз откройте `<адрес Worker'а>/tg/setup` — он подключит вебхук бота. Worker выдаёт служебный вход `tg-…` и пароль, которые может вычислить только он, поэтому утечка его секретов касается только Telegram-аккаунтов. @username хранится в `users/<uid>/tg` и виден в админке.
- Пароль не восстановить: почты нет. Если человек забыл пароль, удалите его аккаунт в админке, и он зарегистрируется заново.

Нужно для работы:
- `FB_API_KEY` (Web API Key из Firebase → Project settings) в `app.html` и `admin.html`. Пока ключа нет, аккаунты выключены.
- Правила из `firebase.rules.json` (в них уже стоит UID администратора). Их вставляют в Firebase → Realtime Database → Rules → Publish.

**После обновления с факультетами — один раз обновите правила базы:** консоль Firebase → Realtime Database → Rules → сотрите старое, вставьте всё содержимое `firebase.rules.json` → Publish.
Без этого сайт тоже работает, но факультет студента запоминается только на его устройстве, а не в аккаунте.

`app.html` — само приложение; `index.html` и `sw.js` собирает `собрать.py`.
